## Approved UX

- Stored recent searches and links get a visible trailing trash button and an equivalent named VoiceOver action. Exact stored UUID determines deletion eligibility; matching title, value, or destination is insufficient.
- Clipboard, saved Library, site, explicit-web, and synthetic nonstored rows have no deletion action.
- Individual deletion has no confirmation. Preserve the current query and keyboard focus. Use sibling open/delete buttons, never nested buttons; both targets remain at least 44 points with visible pressed states.
- Keep the row until the deletion commits. After success remove its UUID locally and synchronously recompose suggestions, then reload history to backfill the current 12-record window. Never reload Library details for this operation.
- Mutation failure retains or reloads existing history with nonblocking Retry/Dismiss feedback. Failed reads never replace known history with an empty array. A committed deletion with failed backfill stays deleted; Retry then refreshes rather than repeating deletion.
- Success copy: “Removed from Search History.” Failure: “Couldn’t remove this item. Try again.” Backfill failure: “Search history changed, but suggestions couldn’t be refreshed.”
- With a manager, stored history is the sole source of recent-link/recent-search rows. Suppress canned recents so a deleted record cannot return as a canned duplicate. Keep clipboard, Library, sites, and final explicit-web action with existing 13.3 routing/deduplication.
- Add a Search History editorial group in Settings after Storage Management. Clear Search History opens a native alert titled “Clear Search History?” with destructive Clear Search History and Cancel actions.
- Confirmation message: “This removes recent searches and links from ToonEdge. Your Library, reading progress, downloads, cookies, and website data are not changed.”
- Cancel/dismiss does nothing. Require pending confirmation to clear, prevent duplicate in-flight requests, disable the action while clearing, and show inline success/failure feedback. Retry reopens confirmation. Success: “Search history cleared.” Failure: “Couldn’t clear search history. Try again.”
- Keep all existing Library organization, including source selection, unchanged by history operations. Zoom remains paused. No new custom haptics, undo, history screen, or source controls.

## Contract and persistence design

Approved interface:

```swift
public protocol SearchHistoryRecording: Sendable {
    func recordSearchHistory(_ input: SearchHistoryInput) async throws
    func recentSearchHistory(limit: Int) async throws -> [SearchHistoryEntry]
}

public protocol SearchHistoryManaging: SearchHistoryRecording {
    func removeSearchHistory(id: UUID) async throws
    func clearSearchHistory() async throws
}
```

Make history reads throwable so errors are distinguishable from empty history. Update every existing caller/spy in the same compiling task; history load failure must not discard successful Library loading.

Inject the same management dependency into Search and Settings through AppDependencies. Add explicit optional `historyEntryID` provenance to SearchSuggestion; only stored recents carry it. Preserve typed destinations and synchronous navigation.

Keep history CRUD in an isolated ModelContext using the existing container, with autosave disabled. Commit one save per effective mutation and roll back only that history context on error. A narrow injected history-save closure enables real repository rollback tests. Never roll back the shared Library context or invoke cache/browser data-clearing APIs.

Mirror behavior in the existing repository dictionary mode and a seeded in-memory manager for mocks. Preserve exact-value recording deduplication and existing UUID on re-record; use deterministic timestamp/UUID ordering. Missing UUID and empty clear are idempotent no-ops without a save. Clear all StoredSearchHistory, including records outside the visible suggestion limit. No persisted schema migration.
