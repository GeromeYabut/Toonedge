# Story 13.2 Guarded Manual Clean Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Reader-entry eligibility an explicit detector result and expose a safe secondary manual action only for viable `45...54` detections.

**Architecture:** Centralize thresholds and viability checks in `ReaderEntryPolicy`; detector paths supply typed hard-block evidence and receive a disposition. Browser consumes disposition without re-reading scores or diagnostic strings and reuses its existing browser-owned Reader presentation path.

**Tech Stack:** Swift 6, SwiftUI, WebKit page analysis, Swift Testing, iOS 17/macOS 14.

## Global Constraints

- High: `>=78`; medium: `55...77`; manual-only: `45...54`.
- Architecture §9.5.1 global floor for every band: `>=4` candidates, or exactly `3` with combined actual rendered height `>=3.5` finite positive viewport heights. Require finite positive rendered measurements for all three; natural size or unknown legacy geometry cannot supply this exception.
- No hard block may expose or honor Clean Mode.
- Automatic, recommended, manual, and unavailable remain visually and behaviorally distinct.
- Failure preserves the exact page and WebView history.
- Do not add bypass behavior for protected content.

```swift
public enum ReaderEntryDisposition: String, Codable, Equatable, Sendable {
    case automatic, recommended, manual, unavailable
}

public enum DetectionHardBlock: String, Codable, Equatable, Hashable, Sendable {
    case challenge, authentication, paywall, errorPage, browserOnly
    case unsupportedPagination, protectedViewer, canvasOrBlob, nonviableSession
}

public struct ReaderEntryEvidence: Equatable, Sendable {
    public var score: Int
    public var negativeScore: Int
    public var candidateCount: Int
    public var tallestHeightRatio: Double
    public var hardBlocks: Set<DetectionHardBlock>
    public var hasViableSession: Bool
    public var totalRenderedHeightRatio: Double
}

public struct ReaderEntryPolicy: Equatable, Sendable {
    public static let architectureDefault = Self(manual: 45, medium: 55, high: 78)
    public let manual: Int
    public let medium: Int
    public let high: Int

    public func disposition(for evidence: ReaderEntryEvidence) -> ReaderEntryDisposition {
        guard evidence.hardBlocks.isEmpty, evidence.hasViableSession else { return .unavailable }
        guard evidence.candidateCount >= 4 || (evidence.candidateCount == 3
            && evidence.totalRenderedHeightRatio.isFinite && evidence.totalRenderedHeightRatio >= 3.5) else { return .unavailable }
        if evidence.score >= high {
            guard evidence.negativeScore > -20,
                  evidence.candidateCount >= 6 || evidence.tallestHeightRatio >= 5 else { return .unavailable }
            return .automatic
        }
        if evidence.score >= medium {
            guard evidence.candidateCount >= 4 || evidence.tallestHeightRatio >= 3.5 else { return .unavailable }
            return .recommended
        }
        if evidence.score >= manual { return .manual }
        return .unavailable
    }
}
```

- [ ] **Step 3: Implement disposition-driven Browser state**

```swift
public enum BrowserCleanModePresentation: Equatable, Sendable {
    case hidden, recommendedBanner, manualTool
}

public func handleDetectionResult(_ result: DetectionResult) {
    detectionResult = result
    readerUnavailableMessage = nil
    switch result.readerEntryDisposition {
    case .automatic: pendingReaderSession = viableReaderSession(from: result.readerSession)
    case .recommended: cleanModePresentation = .recommendedBanner
    case .manual: cleanModePresentation = .manualTool
    case .unavailable: cleanModePresentation = .hidden
    }
}
```

Guard `enterCleanModeManually()` with `.recommended` or `.manual` plus a viable session. Render `Try Clean Mode` in the existing Browser tools, not the primary banner. Preserve the live WebView and show nonblocking feedback when preflight fails.
