# Story 12.3 Browser Editorial Chrome Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Simplify Browser chrome and make Clean Mode a complete, calm, accessible action without touching detection or WebView behavior.

**Architecture:** `BrowserView` owns presentation composition; `BrowserViewModel` continues to own navigation and Reader-presentation state. A small layout policy makes action placement testable, while fixture-backed UI tests verify the rendered behavior.

**Tech Stack:** SwiftUI, WebKit, Swift Testing, XCUITest.

## Global Constraints

- Do not change detection scoring, route observation, retry timing, page analysis, or site profiles.
- WEBTOON and protected GlobalComix remain browser-only and never expose Clean Mode.
- Preserve the live WebView behind browser-owned Reader.
- Preserve Back, Forward, one Reload action, Add to Library when viable, and exact View Original behavior.
- Use stable accessibility identifiers instead of visible `Browser` copy for tests.
- All visible Browser actions are at least 44×44 points.
