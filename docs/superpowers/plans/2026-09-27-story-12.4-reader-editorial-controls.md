# Story 12.4 Reader Editorial Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refine Reader chrome, Reader Settings, and adjacent-load feedback while preserving immersion, typed recovery, and navigation semantics.

**Architecture:** `ReaderViewModel` retains session and operation state. `ReaderView` owns rendering/gesture composition. Reader Settings edits existing `ReaderSettings` only. This story adds no chapter-loading or persistence abstraction.

**Tech Stack:** SwiftUI, Swift Testing, XCUITest, existing typed adjacent loader.

## Global Constraints

- Reader starts with chrome hidden and one reading-surface tap toggles it exactly once.
- Do not add horizontal chapter swipes, double tap, pinch, long press, or edge gestures.
- Back remains origin-aware; Library opens Library root; View Original remains explicit.
- Preserve typed timeout/challenge/unavailable/low-confidence/nonviable adjacent failures.
- Retry remains user initiated and bounded; do not add automatic loops.
- Preserve current chapter/session/progress on failure and cancellation.
- Do not add haptics in this story; Story 12.7 owns feedback semantics.
