# Story 12.7 Semantic Haptics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add sparse, optional, outcome-driven haptics without coupling UIKit feedback generators to feature views.

**Architecture:** Feature code emits semantic events through an injected main-actor protocol. The system adapter maps them to standard feedback only when a separate app-wide interaction preference is enabled. Tests use a recorder; non-UIKit platforms use a silent adapter. The preference is deliberately separate from `ReaderSettings`.

**Tech Stack:** Swift 6, SwiftUI, UIKit `UIFeedbackGenerator` behind conditional compilation, UserDefaults, Swift Testing.

## Global Constraints

- Default Haptic Feedback is enabled and can be disabled immediately in Settings.
- Do not add the preference to `ReaderSettings`; stale Reader snapshots must not overwrite it.
- Do not introduce a SwiftData migration.
- Use standard semantic feedback; do not add custom Core Haptics patterns.
- Visible state remains primary; haptics never replace copy, selection, or recovery actions.
- Automatic detection/Reader entry, scrolling, progress, images, brightness, chrome, background work, cancellation, stale completion, disabled actions, and no-ops remain silent.
- System switches, sliders, and pickers do not receive duplicate feedback.

- [ ] **Step 3: Implement exact contracts**

```swift
public enum InteractionFeedbackEvent: Equatable, Sendable {
    case selectionChanged
    case operationSucceeded
    case chapterTransitioned
    case userActionWarning
}

@MainActor
public protocol InteractionFeedbackProviding: AnyObject {
    func emit(_ event: InteractionFeedbackEvent)
}

@MainActor
public protocol InteractionPreferencesManaging: AnyObject {
    func isHapticFeedbackEnabled() -> Bool
    func setHapticFeedbackEnabled(_ enabled: Bool)
}
```

Persist one namespaced UserDefaults Boolean. Missing/invalid data returns `true`.
