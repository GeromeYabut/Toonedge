# Story 13.5 Library Sorting Design

**Status:** Approved 2026-10-04

## Scope

Story 13.5 adds sorting to the existing Library without adding source filtering. It preserves the Recent, Reading, Planned, Dropped, and Completed segments; Comfortable, Compact, and List layouts; update refresh; genuine empty states; and Series Detail navigation.

Source controls, source preference keys, active-source summaries, and source-filtered empty-state recovery belong exclusively to Story 13.9. Reader zoom has no dependency relationship with this story and its paused worktree must remain untouched.

## Organization model

`LibraryCollectionQuery` is a pure, value-semantic transformation over one existing lightweight `LibrarySnapshot`. It first obtains the selected segment through `LibrarySnapshot.series(for:)`, then orders that projection without mutating the snapshot or loading per-series detail.

The default and Reset organization is:

- Segment: Recent
- Sort: Recent activity
- Direction: newest first
- Density: preserved on Reset

Recent activity uses the existing `LibrarySeriesSummary.lastReadAt`; Story 13.5 does not invent an update-activity timestamp. Dated titles always precede titles with missing dates, including oldest-first ordering. Activity ties resolve by normalized title and stable UUID.

Title ordering uses a deterministic case-, width-, and diacritic-folded key. A–Z and Z–A reverse the primary title comparison; stable UUID resolves equivalent title keys.

Unread updates uses a fixed unread-first order and retains titles without unread updates. Within each unread group, titles use recent activity newest-first, followed by normalized title and UUID. Direction is canonicalized to descending for persisted unread preferences and is not exposed as a control.

## Native sorting control

Library uses one native sort menu near the existing collection controls. The visible value is one of:

- Recent activity · Newest
- Recent activity · Oldest
- Title · A–Z
- Title · Z–A
- Unread updates first

The menu applies choices immediately, exposes the active choice as selected, and provides an accessibility label of “Sort library” with the current ordering as its value. A final `Reset Library organization` action restores Recent plus recent activity newest-first while preserving density.

The control area uses two logical rows: count plus sort, followed by the existing density and refresh controls. `ViewThatFits` may stack count and sort vertically when accessibility text makes the horizontal form unsuitable. Library cards and rows remain cover-first and unchanged.

## Persistence and routing

`LibraryViewPreferences` retains its existing density key and adds independent namespaced keys for segment, sort key, and sort direction. Each value falls back independently when missing or invalid. Reset writes only organization defaults and never changes density.

A pending Library segment supplied by `AppRouter` overrides the restored segment, is consumed once, and becomes the newly persisted segment. Sort interactions never reload the Library service; update refresh continues to refresh the full local Library and the query is reapplied to the returned snapshot.

## Empty states and navigation

Sorting cannot remove titles, so Story 13.5 introduces no filtered empty state. A truly empty Library keeps “Nothing saved,” and an empty lifecycle segment keeps “No titles in this section.” The internal empty reason may be renamed from `filter` to `segment` without changing visible behavior.

Navigation continues to pass the selected `LibrarySeriesSummary` as the seed for native Series Detail. Sorting must not hydrate details until the existing navigation destination does so.

## Verification

Unit tests cover segment composition, activity directions, title directions, unread retention and fixed grouping, nil activity dates, deterministic ties, snapshot immutability, preference round trips, invalid-value fallback, unread-direction canonicalization, Reset, density preservation, and adaptive presentation metadata.

UI tests cover immediate ordering, segment composition, relaunch persistence, Reset with density preservation, accessibility-size usability, refresh preservation, and Series Detail navigation. Final gates include the full package suite, generic simulator build, focused Library UI runs, complete UI suites on the dedicated iPhone 16e and iPhone 16 Pro Max, documentation consistency, and `git diff --check`.
