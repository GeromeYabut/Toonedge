# Reader Interaction and Reconciliation Design

Status: Draft for user review. Story 13.4, next scoped slice after the merged geometry foundations and fitted layout. Baseline: main `cec2f7edfecfa1af0d192f8fa044a4c28a47055b`.

The proposed coordinator preserves the normal reading position while the user inspects enlarged content, and prevents outdated layout or gesture callbacks from replacing newer state. This slice is a pure, deterministic state machine. It does not change the production Reader, write progress, register a native host, or start a native experiment. Approve this design before generating its executable implementation plan or writing product code.

## User behavior

When inspection starts, freeze the normal reading anchor. Pinch and pan change the inspected content point without changing that frozen position. Ending a gesture retains the inspection presentation. Cancellation restores the presentation committed before that gesture, not necessarily 100%. Reset, a zoomed double tap, or a completed return to 100% restores the frozen reading anchor in current geometry. Ordinary scrolling resumes only after the current native layout confirms that restoration.

A newer Reset replaces an older Reset. A late image-size update, old gesture sample, or delayed saved-position restore must not undo the user's latest action. If the current anchor cannot be restored, keep progress suspended and expose an honest recoverable state. Reset and View Original Page remain reachable in the later host; failure never becomes success because a timer expired.

No new visual treatment or gesture tuning is proposed. The approved sticky interaction remains 0.75x through 3x, with the existing downward detent and deliberate breakthrough. This design governs ownership and ordering, not those thresholds.

- `ReaderPresentationTransform` computes bounded presentations and reports their actual projected points. It does not guarantee that the requested point is reachable.
- `ReaderPageMaterializationPolicy` remains independent of interaction state.

Add the future coordinator and its value contracts under `app/Sources/ToonEdgeAppCore/Features/Reader/Interaction/`, with focused tests under `app/Tests/ToonEdgeAppCoreTests/`. Stage 2A completion cannot satisfy Stage 2B or the native adoption gate. ## Architecture choice

| Approach | Tradeoff |
| --- | --- |
| Pure value state machine, recommended | Deterministic transitions and controlled callback tests; the later adapter must serialize events and execute commands. |
| Put coordination in ReaderViewModel | Convenient access to progress, but couples the new interaction to async persistence before commit semantics are proven. |
| Let the native host own all state | Direct native measurements, but ordering becomes difficult to test independently and feasibility code becomes the product model. |

The coordinator receives events and returns immutable state plus explicit presentation requests. It performs no async work, reads no clock, and holds no view or repository reference. One future adapter serializes events on the main actor. A host may apply a command only after confirming its identity is still current; rejecting stale acknowledgements alone cannot undo a stale native mutation.

## State and identity

Keep three anchors/presentations separate:

1. The frozen reading anchor and its required viewport location, captured from the current confirmed baseline when inspection begins.
2. The inspected focal anchor and its required viewport location, updated by accepted pinch/pan interactions.
3. The last committed presentation, represented semantically by scale, anchor, and viewport location so cancellation can reproject it into new geometry rather than reuse an old translation.

A measured baseline reading update advances the normal reading anchor during ordinary scrolling. It is accepted only while baseline reconciliation is current and no inspection gesture is active. The event captures the current token at measurement time and supplies a fresh replacement request UUID; accepting it atomically replaces the confirmed baseline target and readiness receipt without issuing an application command, because the scroll is already measured. Validate actual 1x scale, current decoded geometry, and a bounded transform matching the measured anchor point within tolerance. Old movement events carrying the retired token are inert. At the next inspection the new reading position becomes the frozen anchor; the first-ever anchor must not remain frozen forever.

Use distinct identities with distinct jobs:

| Identity | Purpose |
| --- | --- |
| Content session UUID | Matches the existing geometry and anchor session IDs. |
| Installation UUID | Newly generated for each Reader installation, including reopening the same content session; rejects callbacks from its previous lifetime. |
| Geometry revision UInt64 | Monotonically orders requested geometry snapshots within the installation. |
| Interaction epoch UUID | Changes when a gesture begins, Reset supersedes work, or a discrete interaction begins. |
| Presentation request UUID | Distinguishes every application and acknowledgement, even multiple requests within one gesture or repeated Reset. |

A callback token includes all five identities. A gesture also retains its start epoch; superseding it makes all subsequent samples/end/cancel events for that old gesture inert. Callers supply newly allocated UUIDs explicitly so tests can use stable identities. Exact Swift event/value signatures will be locked in the executable plan after design approval.

State records the latest requested geometry revision, current valid layout, current requested presentation, most recently confirmed presentation, committed rollback target, active gesture, current acknowledgement, and any recoverable failure. Requested and confirmed presentation are not interchangeable. Suggested phases are awaiting initial reconciliation, baseline ready, gesture active, inspection idle, awaiting baseline reconciliation, and recoverable failure. Whether a presentation is awaiting application is orthogonal to the gesture phase.

## Event and command boundaries

Events cover installation, initial restore, confirmed baseline reading position, gesture begin/sample/end/cancel, discrete inspection, Reset, geometry requested/resolved/failed, presentation acknowledgement/failure, and suspension. Discrete inspection supports the approved double-tap and non-pinch accessibility actions without implementing gesture recognizers in this slice.

Commands contain the complete current token, desired bounded transform, semantic target, required viewport point, and purpose: inspection, rollback, initial restore, or baseline restore. There is at most one current presentation request. Replacement retires the previous request, including any baseline readiness receipt it produced.

Suspension rotates the interaction epoch, retires the active gesture and all requests/receipts, and permanently closes the initial-restore window. Ignore gesture, restore, geometry completion, and acknowledgement events while suspended. Retain only semantic anchors, committed target, and the geometry revision watermark for recovery. Resume establishes another new epoch and request and reconciles against a newly requested valid geometry revision; it never reuses a pre-suspension receipt or pending layout completion. An old gesture end/cancel cannot act on the resumed state.

The coordinator validates finite inputs, session identity, valid anchors, and approved scale bounds. It does not calculate pinch detents. Invalid samples cannot mutate a valid presentation; malformed current layout or application results leave reconciliation blocked. Ordinary reading scroll deltas are not routed through inspection pan events.

## Ordered geometry transactions

Every decoded-size, viewport, spacing, fit-mode, rotation, or inset update enters one ordered path. Announcing a newer requested revision immediately retires current acknowledgement/readiness, even before layout construction finishes. Resolve only the latest requested revision; an older completion cannot install its layout. Revisions must not wrap or be reused; revision exhaustion requires a new installation identity rather than wrapping to zero.

If the latest revision fails validation, keep the last valid presentation only as a visual fallback and retain the newer revision watermark. Do not fall back to an older acknowledgement or accept an older build completion. Recovery requires a valid newer revision or a new current request against the now-valid latest layout.

At each valid revision, reproject the active inspected focal anchor and the committed rollback target separately. Preserve the frozen reading anchor unchanged in normalized page coordinates. When restoring baseline, reproject that frozen anchor instead. Commands never reuse translations computed for old page dimensions. An unresolved target page may receive a provisional inspection presentation, but cannot produce baseline readiness; decoding it creates a newer geometry transaction.

Page order is immutable within an installation. Replacing or reordering chapter pages requires a new installation; index-based anchors cannot silently be attached to different content. Removing a target page or producing an out-of-range target is a recoverable failure, not permission to choose an arbitrary nearby page.

Viewport locations are points within the usable viewport after insets. Preserve an accepted semantic location in points across geometry changes; do not silently convert it to a percentage or clamp it into a smaller viewport. If the location falls outside the new viewport or bounded geometry cannot place the anchor within the existing 2-point tolerance on each axis, block reconciliation. This intentionally exposes an impossible restoration rather than presenting a clamped request as exact. Any alternative edge/rotation fallback is a later UX decision, not an implementation assumption.

This strict reprojection rule is distinct from constructing a new user-intent presentation. For pinch, pan, or a discrete off-baseline action, first compute the bounded transform. Keep the inspected anchor if its actual projected point lies within the usable viewport. If pan or clamping moves it outside, rebase the inspection target: intersect each page rectangle with the transform's logical viewport, choose the lowest-index page with positive-area intersection, and capture the center of that intersection as its normalized anchor. Its forward-projected point becomes the new required viewport location. Reconstructing from that anchor and point must reproduce the bounded transform. Never rebase the frozen reading anchor this way.

If no page has positive-area intersection, the proposed sample has no representable visible content target. Reject it before native application, retain the last representable presentation, and expose a recoverable no-content-target failure. Do not manufacture a point in a page gap, an offscreen target, or baseline readiness. A later valid sample in the same gesture, newer valid geometry, or Reset can recover; Original Page remains reachable. This explicit gap behavior avoids extending the geometry API merely to accept offscreen targets.

Reaching a pan limit or centering a non-overflowing 0.75x canvas is therefore not itself failure when content remains visible. The host must acknowledge the accepted bounded target. Subsequent geometry updates and rollback preserve this accepted target strictly; baseline restoration always preserves the frozen reading target, not a newly clamped substitute.

## Gesture completion and recovery

Begin inspection only from a current confirmed presentation with valid anchor capture. Snapshot its semantic rollback target and freeze the reading anchor if transitioning from baseline into inspection. Further inspection gestures keep the original frozen anchor until a successful return to baseline.

Accepted samples update the desired focal presentation and issue fresh request IDs. A gesture's final accepted target becomes its committed semantic presentation on successful end, even if its current native application is pending; it does not become measured readiness. If its application fails, remain recoverable rather than pretending the target was displayed.

Cancellation discards uncommitted samples and issues a new request for the prior committed semantic target in latest geometry. If that target is baseline, restore the frozen reading anchor and await acknowledgement. If it is off baseline, retain inspection state and do not enable progress. A cancellation command is not a baseline acknowledgement.

Reset interrupts any active gesture, creates a new epoch and request, sets the desired scale to exactly 1x, and targets the frozen reading anchor. Repeated Reset does the same again; only the newest request can finish. At an already confirmed baseline, Reset uses the current normal reading anchor rather than an obsolete pre-inspection anchor. A release whose policy result is 1x follows the same baseline restoration path; it is not normal scrolling merely because the number equals one.

Do not accept new gestures while a prior presentation is unconfirmed, because their anchor capture would describe a desired rather than measured surface. Reset, Original Page, suspension, and geometry updates remain available. A failed request can be retried with a new request ID after prerequisites are valid. The future host must expose this recoverable state and provide reachable Reset and Original Page controls; it must not permanently disable reading after recovery succeeds.

## Acknowledgement and readiness

An acknowledgement must match the current installation, content session, revision, epoch, and request. It reports the measured actual scale, projected semantic target point, and that native layout/insets and the target's decoded geometry are current. Actual scale must equal the requested scale exactly, for inspection and rollback as well as baseline. Reject nonfinite measurements, mismatched scale, out-of-tolerance anchors, unresolved targets, or mismatched target identity. A measured 1x surface cannot confirm an unapplied 2x request merely because their focal points coincide. Native completion is measured after applying layout, not inferred from requested values.

Baseline readiness requires no active gesture, measured actual scale exactly 1x, the current baseline target restored within 2 points per axis, and no newer geometry or presentation work pending. A state-changing event immediately retires the old receipt; an accepted measured baseline reading update replaces it atomically with its newly validated receipt as defined above. An acknowledgement during an active gesture may confirm the displayed presentation but never enables baseline readiness; ending at 1x issues its own current baseline request.

Expose a tokenized baseline reconciliation receipt, not a `canSaveProgress` authorization. This receipt establishes only the pure coordinator's presentation precondition. Native measurement provenance, decoded/hittable readiness, visibility, pipeline identity, and repository commit isolation still require later integration tests. Do not treat a synthetic acknowledgement as native evidence. The one-second stability measurement remains a QA acceptance rule, not a production delay.

Installation starts with no readiness. Once a nonempty valid layout exists, seed a default semantic target at page zero's top-center and build a bounded 1x initial presentation. With no pre-existing reading anchor to preserve, its actual bounded projected location becomes the initial required location. Issue an initial application request and require a current decoded acknowledgement before baseline readiness. An empty chapter cannot produce an anchor or readiness; retain the Original Page recovery route. If the target remains unresolved, await a valid decoded geometry revision rather than acknowledge a placeholder.

The initial-restore window is independent of bootstrap readiness: it remains open until the first user interaction, accepted ordinary-reading movement, suspension, or consumption of a restore result. A restore result with no saved position closes the window without changing the default target. A current saved page index seeds a new initial semantic target in latest geometry and uses its actual bounded 1x placement, retiring any pending default command and receipt. This initial placement does not silently relax a later frozen-anchor restoration. Reject invalid saved indexes rather than attaching them to arbitrary content.

Capture the installation identity when launching the restore; after the window closes, all late results are inert. Starting Reset or inspection retires it permanently for that installation. No saved normalized anchor is introduced into persistence. Before baseline confirmation, Reset retries the current initial target if available; it never invents a frozen anchor. Without a valid initial target it reports recoverable failure and keeps Original Page reachable.

## Delivery outline and test matrix

After approval, generate a separate executable plan with concrete Swift signatures, complete RED/GREEN test steps, and independently reviewable commits. Proposed order:

1. Identity contracts, installation/reset/suspension invalidation, and initial-restore fencing.
2. Requested versus confirmed presentations, reading versus focal anchors, gesture commit/cancel, and discrete actions.
3. Ordered geometry updates, failure watermark, semantic reprojection, and tokenized acknowledgement/readiness.
4. Complete deterministic regressions, iOS package compile, package regression, independent review, and PR delivery.

| Scenario | Required pure assertion |
| --- | --- |
| Inspect and pan above or below baseline | Frozen anchor unchanged; current focal and committed targets remain distinct; no baseline receipt. |
| Cancel before and after a geometry update | Restore prior committed semantic target using current layout; old translations and callbacks rejected. |
| End at 1x | Remain blocked until the new baseline request is measured and current. |
| Repeated Reset | New epoch/request each time; first acknowledgement cannot enable readiness. |
| Rapid revisions, including latest invalid | Highest requested revision owns ordering; older valid layout/ack cannot revive readiness. |
| Differing decoded dimensions | Same normalized target reprojects through new geometry; unresolved target cannot acknowledge baseline. |
| Fit, spacing, insets, rotation and narrow viewport | Ordered revision; explicit failure for unreachable target, not fabricated continuity. |
| Session reinstall with same content UUID | Old installation callbacks, restore results and receipts are rejected. |
| Late restore after any user interaction | No overwritten presentation or anchor. |
| Resume baseline reading then inspect again | New reading position freezes; successful recovery enables a fresh receipt rather than permanent suspension. |
| NaN, infinity, invalid anchors, exhausted revisions | No corrupt transform or accidental readiness; recoverable current failure where appropriate. |
| Suspension during pending application | Old application/ack cannot mutate or resume a resumed installation. |
| No saved progress and delayed initial restore | Default placement requires acknowledgement; a current restore supersedes it, but no late restore survives user movement or suspension. |
| Pan at bounds or below-baseline centering | Confirm actual bounded user-intent target; keep strict target fidelity across later geometry changes. |
| Pan moves old focal point offscreen, or enters a page gap | Rebase to deterministic visible content and reproduce the transform; with no intersecting page reject before application and preserve the prior representable state. |
| Measured scale differs from requested scale | Reject acknowledgement even when the focal point matches; do not permit gestures based on unapplied scale. |

Controlled value tests demonstrate ordering and contract behavior only. No persistence spies are claimed in Stage 2A. Stage 2B must audit `markImageVisible`, `markImageReady`, readiness subscriptions, `restoreProgress`, `replaceSession`, and `updateProgress`, including progress save, metadata enrichment, recent reading, cache metadata, and completion consequences across every await. An entry guard or task cancellation cannot retract a repository write already started; adoption remains blocked until commit isolation is proven with actual implementations and controlled spies.
