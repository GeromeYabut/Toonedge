## Delivered behavior

- One chapter-scoped observable pipeline owns loading and decoded images.
- The working window is the current page, two ahead, and one behind; the scheduler caps concurrent operations at three and deduplicates URLs.
- Loading uses decoded memory, retained chapter assets, then network. Speculative loading does not mark chapters retained offline.
- ImageIO decodes eagerly off the main actor. Cancelled work remains accounted for until it terminates; stale results cannot update a cancelled pipeline.
- Actual viewport geometry selects the current page, including backward scrolling and same-index chapter replacement. Progress can select the ready final page when its bottom is visible; loading remains anchored to the topmost intersecting panel so earlier visible panels stay loaded. Existing page-based progress remains unchanged for tall final pages.
- Progress persists only for the selected ready page, including a stationary transition from placeholder to ready.
- Lightweight learned dimensions survive decoded-image eviction. Page-local terminal failures wait for explicit Retry; transient network loading retains two attempts with a 250 ms delay.
- Existing reader canvas, source-page actions, request context, and accessible image labels remain available. No persistence schema change.

## Failures found and corrected

- Detached decoding now waits for child termination and rejects caller cancellation before returning a decoded image.
- Configurable concurrency is clamped to the required maximum of three.
- Cancellation/revisit tests use bounded lifecycle synchronization rather than fixed timing sleeps. An additional command-processing barrier closes a reproduced test race.
- Viewport tracking replaces lazy-cell appearance tracking. Pipeline identity re-arms visibility after chapter replacement.
- Labelled CGImage rendering restores the image accessibility role queried by long-chapter and offline UI tests.
- Direct pipeline-state observation closes a stationary-ready progress subscription gap; readiness is also checked when visibility registers after decoding.
- Learned dimensions remain after eviction, preventing metadata-free tall-page placeholders from collapsing to the default height.
- The new loading path restores the old bounded retry policy. Terminal failures remain sticky when the prefetch window moves, so speculative work cannot silently consume the explicit-retry fixture.
- Offline UI setup waits for `reader.root`, rather than a Home scroll view that can exist before Reader presentation.
- The completion override is separate from the loading anchor. A real 40-page pipeline regression keeps three intersecting ready panels decoded while final-page progress reaches 100%; anchor-only changes still reprioritize loading.

Earlier full runs at `2c9315b` and `8b9c444` failed and remain diagnostic evidence, not passing release gates. At `72c8766`, both devices passed 47/48 tests but reported 95% at chapter end. Both passed 48/48 at `6f5aef6`; code review then identified the visible-window eviction corrected in the final revision. The isolated Library mutation-retry test passed on unchanged `main`; no Library production code was changed in response to its intermittent full-suite failure.
