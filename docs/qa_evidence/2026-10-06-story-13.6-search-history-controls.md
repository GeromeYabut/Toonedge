## Behavior and architecture

`SearchHistoryManaging` extends recording/throwing reads with exact UUID removal and clear-all. SwiftData history operations use a fresh, autosave-disabled context, one save per effective mutation and isolated rollback. Missing IDs and empty clear are no-ops. Persistent, dictionary and seeded actor implementations retain UUIDs during exact-value recording deduplication and use deterministic ordering. No schema migration.

Search and Settings receive the same manager. Only stored recent query/link suggestions carry deletion provenance; clipboard, saved Library, sites and explicit web actions have no deletion control. Sibling open/delete buttons and an equivalent named accessibility action preserve existing destinations, copied-link precedence, deduplication and the final web action. Successful removal synchronously recomposes suggestions before refreshing the 12-record window without refetching Library. Failure keeps known state and offers Retry/Dismiss; refresh failure after a committed removal retries reading, not deleting.

Settings presents a native confirmation titled “Clear Search History?” with destructive “Clear Search History” and “Cancel”. Copy:

> This removes recent searches and links from ToonEdge. Your Library, reading progress, downloads, cookies, and website data are not changed.

Cancel/dismiss performs no operation. A pending-confirmation guard prevents unconfirmed or duplicate in-flight clearing. Retry reopens confirmation. History operations delete only `StoredSearchHistory`; no cache, settings, Library or WebKit clearing API is called by production code.
